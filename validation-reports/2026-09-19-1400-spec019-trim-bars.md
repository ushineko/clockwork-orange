## Validation Report: Spec 019 — Trim flat bars, and say what an API failure means

**Date**: 2026-09-19 14:00
**Spec**: specs/019-trim-flat-bars-and-read-api-failures.md
**Issues**: #21, #22
**Status**: PASSED

### Summary

Two findings from one download run.

**Bars (#21).** Downloaded wallpapers sometimes arrive at the right resolution
with flat padding baked in, and the cover-crop preserves it. The reported
example is white, luma 255.0 with a maximum deviation of 0.0 across the column,
ending at a column whose deviation is 134 — exact, not heuristic.

The work was not the detection, it was refusing to over-detect. A naive scan
claimed bars on **70 of 638** real wallpapers, including `L2736 R2736` on a
5760-pixel-wide picture: it had marched through the flat regions of dark space
scenes and minimalist designs. Cropping on that would have destroyed one
wallpaper in ten to fix one in seventy. Four guardrails — a width cap, a
required luma step at the boundary, a floor on what survives, and a minimum run
length — bring it to **8 (1.3%)**, all genuine.

**The outage (#22).** Measured live: `wallhaven.cc/` returns 200, the API
returns 503 to our User-Agent and to a browser's alike, the image CDN returns
521, and the same API through a third-party proxy on a different IP returns
522. Cloudflare cannot reach the origin. Not a bot challenge, not an IP block,
not the missing key. The request was right; the reporting around it was not.

### Phase 4: Code Quality

- `make lint`: **0 issues**. Two findings on the first pass, both fixed rather
  than suppressed: `cap` and `max` shadowed builtins.
- `trim.go` carries the reasoning at the top — why each guardrail exists and
  what the naive version did without it — because the next person to loosen a
  threshold needs to know what it is holding back.
- No duplication: one detector, used by a rectangle-returning call for the
  plugin that already decodes and a file-rewriting call for the one that does
  not.

### Phase 5: Security Review

- `govulncheck ./...`: **no vulnerabilities found**.
- `TrimBarsFile` rewrites a file the plugin itself just wrote, at a path it
  constructed; no user input reaches it and no new path is opened.
- The trim is bounded by the image's own dimensions, so a crafted image cannot
  drive an out-of-range crop — `TrimBars` returns a rectangle inside the
  source's bounds by construction.
- Truncating an error body to 200 characters also stops a hostile or enormous
  response from filling the log, which is a small hardening in its own right.
- No network change, no new external command, no credentials.

### Phase 5.5: Release Safety

- **Rollback**: revert the commit; v4.2.6 is installable from the AUR and the
  GitHub artifacts.
- **Nothing on disk is modified by this change.** Both call sites are in the
  download pipeline; no path walks an existing directory. A rollback therefore
  leaves no residue.

### Not verified

That a newly downloaded padded image comes out trimmed on the affected machine.
The detector is verified against that machine's whole corpus and the pipeline
wiring is covered by the plugins' own tests, but the two have not been observed
end to end in a live run — the Wallhaven API is down, and a padded DuckDuckGo
image has to turn up.

**PASSED.**
